## 목표

1. 검색 방문자가 테스트를 완료하고 다음 콘텐츠로 자연스럽게 이동하게 한다.
2. 심리테스트, 밸런스게임, 미니게임을 번갈아 소개해 재방문 이유를 만든다.
3. 실제 이용 데이터로 제목, 내부 링크, 오늘의 콘텐츠 편성을 개선한다.
4. AdSense 승인 전에는 광고 코드를 활성화하지 않고 콘텐츠 품질과 정책 준수를 먼저 확보한다.

## 반복 운영 절차

1. GitHub `main`과 작업 트리 상태를 확인한다.
2. 한 번에 하나의 콘텐츠 목적과 독자 질문을 정한다.
3. 중복 문장, 과장, 허위 수치, 근거 없는 전문가 인용을 제거한다.
4. 공개 전 독립 URL, 제목, 설명, canonical, 구조화 데이터와 모바일 화면을 검증한다.
5. Blogger는 `automation/blogger/content.json`의 `revision`을 올리고 검증 후 6시간 트리거로 동기화한다.
6. 배포 후 실제 URL과 오류 로그를 확인하고, 실패 시 수정·재검증한다.

## 데이터 기반 의사결정 규칙

- 참여자 수, 득표율, 점수, 방문 수는 Firebase·GA4·Search Console에서 실제로 수집된 값만 사용한다.
- 표본이 적을 때는 인기나 효과를 단정하지 않고 ‘최근 이용 기록’처럼 사실에 맞는 표현을 쓴다.
- 제목 변경은 한 번에 한 요소만 바꾸고 변경 시점과 이유를 기록한다.
- 방문 증가보다 테스트 완료, 다음 콘텐츠 이동, 재방문처럼 서비스 가치와 연결된 지표를 우선 본다.
- 로그인하지 않은 이용자에게 불필요한 개인정보 입력을 요구하지 않는다.

## 광고 준비 안전선

- 승인된 AdSense 게시자 ID가 없으면 광고 스크립트, 광고 단위와 `ads.txt`를 생성하지 않는다.
- 광고를 콘텐츠 버튼, 투표 선택지, 게임 조작부와 혼동되게 배치하지 않는다.
- 클릭 요청, 클릭 보상, 반복 새로고침 유도, 수익 보장을 사용하지 않는다.
- AdSense 실제 신청, 법적 동의와 계약은 계정 소유자가 직접 검토한 뒤 진행한다.
